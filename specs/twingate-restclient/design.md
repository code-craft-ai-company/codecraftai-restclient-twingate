# Design

## Overview

`TwingateClient` is a `RestClientBase` subclass that POSTs GraphQL bodies to a
single endpoint. The endpoint URL is derived from the credential's network slug
(`https://<slug>.twingate.com/api/graphql/v1`). All requests share auth, headers,
and aspects via the base.

The client implements `IVPNControlPlane` from `automojo-interfaces`. Once published,
the M3-landed `automojo-interop/vpn/twingate/twingatecontrolplane.py` reduces to a
one-line re-export shim emitting `DeprecationWarning` for one release cycle.


## apply_acl — Three-Phase Algorithm

Tailscale-shaped flat-ACL JSON does not have a 1:1 Twingate representation. The
translator below converges arbitrary input documents to a Twingate state.

```
INPUT: acl_doc (Tailscale-shaped)
       — parse into intermediate Resources, Groups, Edges

CURRENT: read existing state via three list operations
         → current_resources, current_groups, current_edges

PHASE 1 — Resources
  desired_resources = set(intermediate.resources)
  for r in desired_resources - current_resources: create
  for r in desired_resources ∩ current_resources where attrs differ: update
  for r in current_resources - desired_resources: delete

  pause(mutation_dependency_pause_seconds)

PHASE 2 — Groups
  desired_groups = set(intermediate.groups)
  ... (same shape as Phase 1)

  pause(mutation_dependency_pause_seconds)

PHASE 3 — Resource-Group Assignments (edges)
  desired_edges = set(intermediate.edges)
  for e in desired_edges - current_edges: resource_access_add(...)
  for e in current_edges - desired_edges: resource_access_remove(...)
```

Idempotence is achieved by the set-diff: a second `apply_acl` with the same input
produces empty diffs in all three phases and issues no mutations.

The `mutation_dependency_pause_seconds` is configurable via aspects; it defaults to
a small positive value so that downstream Twingate state propagation is observable
before edges are added. Set to 0 for testing.

## Data Model

`IVPNControlPlane` accepts and returns the protocol-declared dataclasses. The api-group
methods accept and return the generated `SchemaObject` classes from `twingate-schema-import`.
Adapters translate between the two — kept thin so the boundary is visible.

## Testing Strategy

**Example-based tests:**
- Construct with a `TwingateServiceAccountCredential`; verify endpoint URL composition.
- Mock HTTP fixtures for each api-group method; verify the GraphQL body, variables, and `operationName` of each request.
- `isinstance(TwingateClient(...), IVPNControlPlane)` runtime check.
- `mint_authkey`: tag→connector resolution success, unresolved-name failure, multi-tag SemanticError.
- `apply_acl`: minimal three-phase happy path, second-call idempotence (zero mutations), malformed input → SemanticError.

**Property tests (hypothesis):**
- For any valid acl_doc input, `apply_acl` is idempotent: applying twice issues mutations only on the first call.
- For any valid acl_doc input, the order of resources/groups/edges in the input does not affect the final Twingate state.
- Builder determinism (covered in the schema-import feature but verified end-to-end here).
- Adapter symmetry: `VPNDeviceRecord` ↔ `TwingateDevice` round-trip preserves the shared fields.
